# Fireflies AI Clone — Meeting Notes & Transcription Platform

A full-stack clone of the [Fireflies.ai](https://fireflies.ai) meeting-assistant workspace, built for the Scaler SDE
Fullstack assignment. Users can browse a library of meetings, read an interactive transcript that stays in sync with a
player, view an AI-style summary with chapters and action items, and create, edit and delete meetings.

Transcripts are seeded or importedfrom text, and summaries are seeded or generated by a deterministic heuristic.

| | |
|---|---|
| **Live app (frontend)** | https://fireflies-ai-clone-eight.vercel.app |
| **Live API (backend)** | https://fireflies-ai-clone-1-8bho.onrender.com (interactive docs at `/docs`) |
| **Source** | https://github.com/GitSamarth/fireflies-ai-clone |

> The backend runs on Render's free tier: the first request after idle can take up to about a minute (cold start),
> and the filesystem is ephemeral (see [Deployment](#deployment)).

## Features

**1. Meetings library (dashboard)**
- Past meetings with title, date, duration and participants, grouped by day
- Search by title or participant (debounced), participant filter, From/To date filters
- Sort by most recent or oldest, clear-filters, "Load more" pagination
- Navbar with profile menu and notification placeholders; sidebar navigation

**2. Meeting detail**
- Timestamped transcript with speaker labels
- Player with play/pause, seek bar, ±10 s skip, playback speed, chapter ticks on the seek bar
- Click a transcript line → player seeks to that timestamp
- Player position → the active transcript line is highlighted and followed (auto-scroll pauses if you scroll manually;
  a "Follow playback" button resumes it)
- In-transcript search with highlighted matches, "n of N" counter, next/previous (Enter / Shift+Enter)

**3. Summary & notes**
- Summary overview, keywords (key topics), outline/chapters (click a chapter → seeks the player), bullet-point notes
- Action items panel

**4. Meeting management (CRUD)**
- **Create** by pasting a transcript or uploading a `.txt`, `.vtt` or `.json` file
- **Edit** title and participants
- **Delete** with a confirmation dialog (cascades to transcript, summary, chapters and action items)
- **Action items:** add, edit (text / assignee / due date), complete, delete. Completion and delete are optimistic and
  roll back with an error toast if the request fails
- Everything persists in SQLite

**5. Fireflies-style experience**
- Left-rail layout (library + detail), summary and transcript panels, modals and forms
- Success / error / info toasts
- Loading skeletons, empty states, error states with retry
- Settings page and "Coming soon" placeholders (AI Apps, Integrations, Team, Billing, etc.)

**Placeholders (as permitted by the assignment):** live meeting bot, real speech-to-text, Zoom/Meet/calendar/CRM
integrations, team sharing, real authentication (a fixed "Demo User" is always signed in).

**Bonus:** a cross-meeting transcript search API (`GET /api/search`) exists; a UI for it is not built.

## Setup instructions

**Prerequisites:** Python 3.11+ (3.12 used), Node.js 20+ and npm, Git.

### 1. Clone
```bash
git clone https://github.com/GitSamarth/fireflies-ai-clone.git
cd fireflies-ai-clone
```

### 2. Backend → http://localhost:8000

**Windows (PowerShell)**
```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload
```
> If PowerShell blocks the activation script, run once:
> `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`

**macOS / Linux**
```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload
```

On first start the app creates `backend/fireflies.db` and seeds 5 sample meetings. Open
http://localhost:8000/docs for the interactive API docs and `http://localhost:8000/api/health` for a liveness check.

### 3. Frontend → http://localhost:3000

In a second terminal:

**Windows (PowerShell)**
```powershell
cd frontend
Copy-Item .env.example .env.local
npm install
npm run dev
```

**macOS / Linux**
```bash
cd frontend
cp .env.example .env.local
npm install
npm run dev
```

Then open **http://localhost:3000** (use `localhost`, not `127.0.0.1`, unless you add that origin to `ALLOWED_ORIGINS`).

### Environment variables

| Variable | Where | Default | Purpose |
|---|---|---|---|
| `NEXT_PUBLIC_API_URL` | frontend | `http://localhost:8000` | Backend base URL, no trailing slash. **Baked in at build time**, so redeploy after changing it |
| `DATABASE_URL` | backend | `sqlite:///./fireflies.db` | SQLAlchemy database URL |
| `ALLOWED_ORIGINS` | backend | `http://localhost:3000` | Comma-separated CORS allow-list (set to the Vercel URL in production) |

### Reset the database
Stop the backend, delete the file, restart (it re-seeds automatically):
```powershell
Remove-Item backend\fireflies.db        # Windows
```
```bash
rm backend/fireflies.db                 # macOS / Linux
```

### Run the tests
```bash
cd backend  && python -m pytest -q
cd frontend && npm test && npm run lint && npx tsc --noEmit && npm run build
```

## Architecture overview

```
 Browser
   │
   ▼
 Next.js 15 (client components, App Router)            Vercel
   │  fetch + JSON  (lib/api.ts)
   ▼
 FastAPI                                                Render
   ├─ routers/       HTTP layer, validation, status codes
   ├─ services.py    use-cases (create meeting = parse → summarize → persist in one transaction)
   ├─ parsing.py     .txt / .vtt / .json / pasted text  →  normalized segments
   ├─ summarizer.py  deterministic heuristic summary, chapters, action items
   ├─ seed.py        sample meetings, created on first start if the DB is empty
   └─ models.py      SQLAlchemy ORM
   ▼
 SQLite (fireflies.db)
```

**Request flow example — completing an action item:** checkbox click → `ActionItems` flips state optimistically →
`PATCH /api/action-items/{id}` `{completed: true}` → router validates with Pydantic → updates the row → returns the
item → UI reconciles (or rolls back and shows an error toast if the request failed).

**Transcript ↔ player sync:** `hooks/usePlayer.ts` exposes one interface (`currentMs`, `seek`, `play`, `pause`,
`rate`) over two backends: a real `<audio>` element when a meeting has a `media_url`, otherwise a simulated clock. The
transcript only consumes `currentMs`; the active line is found with a binary search over segment start times
(`activeIndex()` in `lib/format.ts`, O(log n)).

**Frontend structure:** pages in `src/app`, UI in `src/components`, the player hook in `src/hooks`, and the typed API
client plus helpers in `src/lib`.

## Database schema

SQLite, managed with SQLAlchemy 2. Tables are created at startup with `create_all()`.

```
meetings
  ├──< participants          (many per meeting)
  ├──< transcript_segments   (many per meeting, ordered by idx)
  ├──1 summaries             (one per meeting)
  ├──< chapters              (many per meeting)
  └──< action_items          (many per meeting)
```

### `meetings`
| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | |
| `title` | VARCHAR(200) | |
| `started_at` | DATETIME, indexed | Stored as naive UTC |
| `duration_ms` | INTEGER | End of the last transcript segment |
| `media_url` | VARCHAR(500), nullable | If set, the player uses a real `<audio>` element |
| `created_at`, `updated_at` | DATETIME | |

### `participants`
| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | |
| `meeting_id` | FK → meetings.id, `ON DELETE CASCADE`, indexed | |
| `name` | VARCHAR(120) | `UNIQUE (meeting_id, name)` |

### `transcript_segments`
| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | |
| `meeting_id` | FK → meetings.id, `ON DELETE CASCADE` | Composite index `(meeting_id, start_ms)` |
| `idx` | INTEGER | Order within the meeting |
| `speaker` | VARCHAR(120) | Speaker label as it appears in the transcript |
| `start_ms`, `end_ms` | INTEGER | Milliseconds from the start of the meeting |
| `text` | TEXT | |

### `summaries` (1:1 with meetings)
| Column | Type | Notes |
|---|---|---|
| `meeting_id` | PK and FK → meetings.id, `ON DELETE CASCADE` | |
| `overview` | TEXT | |
| `keywords` | JSON list | Key topics |
| `notes` | JSON list | Bullet-point notes |
| `source` | VARCHAR(20) | `seed` or `heuristic`, so the UI can label provenance honestly |

### `chapters`
| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | |
| `meeting_id` | FK → meetings.id, `ON DELETE CASCADE`, indexed | |
| `start_ms` | INTEGER | Makes each chapter clickable → seek |
| `title` | VARCHAR(200) | |

### `action_items`
| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | |
| `meeting_id` | FK → meetings.id, `ON DELETE CASCADE`, indexed | |
| `text` | TEXT | |
| `assignee` | VARCHAR(120), nullable | |
| `due_date` | VARCHAR(10), nullable | `YYYY-MM-DD` |
| `completed` | BOOLEAN | |
| `created_at` | DATETIME | |

### Why it is designed this way
- **Integer milliseconds** for all timestamps: seek and sync comparisons are exact, with no float or string parsing.
- **Action items are rows, not a JSON blob:** each one can be edited, completed or deleted independently, and the
  library can count open items cheaply.
- **Chapters store `start_ms`** so the outline is directly seekable.
- **Participants are separate from speakers:** attendees can be edited without rewriting transcript rows.
- **Keywords and notes are JSON** because they are always read and written whole.
- **Cascade deletes** are enforced in two places: ORM `cascade="all, delete-orphan"` and database `ON DELETE CASCADE`
  with `PRAGMA foreign_keys=ON` (SQLite ignores foreign keys unless this is enabled on every connection).
- **`summaries.source`** records whether a summary was seeded or heuristically generated.

## API overview

Base URL: `http://localhost:8000` locally, `https://fireflies-ai-clone-1-8bho.onrender.com` in production. All bodies
are JSON. Full interactive documentation (OpenAPI) is at `/docs`.

| Method & path | Description |
|---|---|
| `GET /api/health` | Liveness check → `{"status":"ok"}` |
| `GET /api/meetings` | List meetings → `{items, total}`. Query: `q` (title or participant), `participant`, `date_from`, `date_to` (`YYYY-MM-DD`, inclusive), `sort` = `recent` (default) or `oldest`, `limit` (1–200, default 50), `offset` |
| `GET /api/meetings/participants` | Distinct participant names (for the filter dropdown) |
| `POST /api/meetings` | Create a meeting from a transcript. Parses it, generates a summary, chapters and action items, and stores everything in one transaction. Returns `201` with the full meeting |
| `GET /api/meetings/{id}` | Meeting detail: segments, summary, chapters, action items |
| `PATCH /api/meetings/{id}` | Edit `title` and/or `participants` (at least one participant is required) |
| `DELETE /api/meetings/{id}` | Delete the meeting and everything under it → `204` |
| `POST /api/meetings/{id}/action-items` | Add an action item `{text, assignee?, due_date?}` → `201` |
| `PATCH /api/action-items/{id}` | Edit `text`, `assignee`, `due_date`, `completed`. An explicit `null` clears assignee or due date |
| `DELETE /api/action-items/{id}` | Delete an action item → `204` |
| `GET /api/search?q=` | Cross-meeting transcript search (`q` ≥ 2 characters) → hits with meeting, speaker, timestamp and snippet |

**Create request**
```json
POST /api/meetings
{
  "title": "Weekly Product Sync",
  "transcript": "[00:00] Sarah: Welcome everyone.\n[00:08] Marcus: I'll share the Q3 numbers.",
  "filename": "sync.txt",
  "started_at": "2026-03-02T10:00:00",
  "participants": ["Sarah", "Marcus"]
}
```
Only `title` and `transcript` are required. `filename` is a format hint (`.vtt`, `.json`, `.txt`). `participants`
defaults to the distinct speakers. Title must be 1–200 characters; transcript up to 1,000,000 characters.

**Errors** use standard HTTP codes: `404` unknown meeting or action item, `422` validation failures or an unparseable
transcript (the `detail` field contains a human-readable message). Failed imports leave nothing behind in the database.

## Transcript import formats

| Format | Example | Timing |
|---|---|---|
| Timestamped text | `[00:12] Alice: Hello` or `Alice [00:12]: Hello` or `00:12 Alice: Hello` | Taken from the file |
| Plain text | `Alice: Hello` | Estimated from word count (about 2.6 words per second) |
| WebVTT (`.vtt`) | cues with `00:00:01.000 --> 00:00:04.000` and `<v Alice>text</v>` or `Alice: text` | Taken from the cues |
| JSON (`.json`) | `[{"speaker":"Alice","text":"Hi","start":1.5,"end":3}]` or `{"segments":[...]}`. Accepts `start`/`end` in seconds, or `start_ms`/`end_ms` | Taken from the file, estimated if absent |

Lines that do not start a new speaker turn are appended to the previous turn. Out-of-order start times are made
monotonic. Empty or unparseable input is rejected with a clear error.

## Assumptions

- **Transcription is mocked.** Meetings come from seed data or from transcript text the user pastes or uploads.
- **Summaries are mocked.** Seeded meetings have hand-written summaries. Imported meetings get a deterministic
  keyword/regex summary (overview, keywords, chapters, notes and detected action items). No LLM is called, so no API key
  is needed. The UI labels which kind a summary is.
- **The player is a placeholder.** Seeded and imported meetings have no audio file, so the player runs a simulated
  timeline (labelled "placeholder audio"). Setting a meeting's `media_url` makes the same player drive a real
  `<audio>` element with no UI changes.
- **No real authentication.** A fixed "Demo User" is always signed in; Sign out only shows a notice.
- **Integrations, team/sharing, AI Apps and most settings are placeholders** marked "Coming soon".
- **Seeded meetings are condensed** (about 1–2 minutes of transcript each) so the demo is quick to read.
- **Time handling:** timestamps are stored as naive UTC and displayed in the viewer's local time.
- **Single-user data model:** there is no per-user ownership of meetings.

## Known limitations

- Heuristic summaries and action-item detection are simple and will miss or mislabel things on real transcripts.
- Editing a meeting's participants does not rename the speaker labels inside the transcript.
- Schema is created with `create_all()`; there are no migrations.
- Global search is a `LIKE` scan (fine at this scale); full-text search (SQLite FTS5) would be the next step.
- Very long transcripts render every segment (no virtualization yet).
- The real `<audio>` playback path exists but is not covered by automated tests, because the sample data has no
  audio file.
- Render's free tier sleeps when idle and its disk is ephemeral: user-created meetings can disappear after a restart or
  redeploy, and the seed data is recreated. Use a persistent disk or Postgres to keep data.
- Visual styling follows Fireflies' general look (violet accent, left rail, card list, split summary/transcript view); it
  is not a pixel-exact reproduction.

  start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`; health check `/api/health`

  build time)

## Design decisions

- **Plain CSS and a small component set** instead of a UI library: fewer dependencies and complete control over the
  Fireflies-style layout.
- **One player abstraction** so transcript syncing does not depend on whether audio is real or simulated.
- **Optimistic updates with rollback** for action items, so toggling feels instant but never lies about a failed save.
- **Server-side filtering and pagination** for the library; **client-side search inside a meeting** for instant
  highlighting.
- **Request-race protection:** the library cancels superseded requests and ignores any response that is no longer
  the latest.
- **Heuristic summarizer behind a clear seam** (`summarizer.summarize`) so an LLM implementation can replace it without
  touching routers or the UI.
